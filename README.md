# OIDC Login for Jellyfin

A Jellyfin 12.x plugin that lets people sign in to the Jellyfin web UI through one OpenID Connect Identity Provider. It is tested against PocketID, so passkeys become the way into Jellyfin. Jellyfin's own username-and-password sign-in (Local Login) keeps working unless you restrict it.

## Installing

The Plugin is published in its own plugin repository, so Jellyfin installs and updates it like any other plugin.

1. In Jellyfin, open **Dashboard → Plugins**, go to **Repositories**, and add a repository:
   - **Name:** `OIDC Login`
   - **URL:** `https://nicoflink.github.io/jellyfin-oidc-plugin/manifest.json`
2. Open **Catalog**, find **OIDC Login** under *Authentication*, and install it.
3. Restart Jellyfin.

Each release is built for one Jellyfin minor version and needs at least that version. Jellyfin only offers releases whose target version your server meets, so update Jellyfin first if the latest release doesn't show up.

## Restricting Local Login

On the Plugin's configuration page, the **Local Login** step sets where password sign-in is accepted:

- **Allowed** (the default): everywhere, as without the Plugin.
- **Local network only**: only from the LAN networks set in Jellyfin's networking settings. From the internet, password sign-in is refused.
- **Disabled**: nowhere.

OIDC Login and Quick Connect are never restricted, so native and TV apps sign in by approving a Quick Connect code from a web session signed in through your Identity Provider. Keep Quick Connect switched on in Jellyfin. A refused password sign-in gets `403` before the password is checked, and jellyfin-web's login page hides the password form. The policy takes effect only once the Plugin is fully configured, and stays in force while the Identity Provider is down.

**Getting back in:** if your Identity Provider breaks while Local Login is restricted, sign in from the local network (with **Local network only**), or disable or remove the Plugin. Nothing is written to Jellyfin's users, so Local Login works again immediately.

**Behind a reverse proxy:** with **Local network only**, add the proxy's address to **Known Proxies** in Jellyfin's networking settings. Otherwise Jellyfin sees every request as coming from the proxy, which is usually local, and lets the whole internet sign in with a password. The configuration page warns when it detects this.

## Releases

Releases come only from the [Release workflow](.github/workflows/release.yml). The version is the git tag `vMAJOR.MINOR.PATCH`; nothing commits to `main`.

- **Automatic:** a push to `main` that changes `targetAbi` in `build.yaml` (a Jellyfin bump) releases the next patch, with the notes "Built and tested against Jellyfin 12.N".
- **Manual:** run the workflow from the Actions tab and choose `major`, `minor` or `patch`. The notes are generated by GitHub.

Each release attaches the jprm-built zip and its `.md5` to the GitHub Release and adds the version to `manifest.json` on the `gh-pages` branch.

## Dependency updates

[Renovate](renovate.json) keeps the Plugin built and tested against the Jellyfin it targets. Its dependency dashboard is an issue in this repository.

- **Jellyfin:** the `jellyfin/jellyfin` test image, `Jellyfin.Controller`, `Jellyfin.Model` and `targetAbi` move together in one PR, opened once all four have a new version (NuGet publishes before Docker Hub). Green minor and patch bumps merge on their own, and the merge releases the next patch (see above).
- **PocketID:** the test image is merged on its own when green.
- **Everything else:** one weekly PR (Monday morning, UTC), merged when green. Releasing these is a manual decision.
- **Majors** always get their own PR and wait for the maintainer.

Automerge goes through GitHub's native auto-merge, so a PR merges only after the required `unit` and `e2e` checks pass. `.github/scripts/renovate-config.test.sh` checks `renovate.json` against real Renovate (needs podman or docker and network); the Renovate config workflow runs it when the config changes.
